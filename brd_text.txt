2. Executive Summary
This document defines the business and functional requirements for a production-grade, web-based Tour & Activity
Booking Platform. The platform allows customers to browse tours/services, check real-time slot availability, book
online, and pay either through the AmwalPay payment gateway or via a manual bank-transfer-with-screenshot
workflow that is verified by an admin. It integrates deeply with the WhatsApp Cloud API so that customers can check
availability, book, and track orders directly inside WhatsApp chat, supported by rich message templates (including
media and carousels), a bot/automation builder, and an AI chat assistant. A full-featured admin panel gives the
business owner complete control over bookings, orders, payments, staff, WhatsApp/email marketing, and reporting.
The system is designed around four pillars:
• Booking Engine: slot-based availability, multi-service booking, and order lifecycle management
• Payments: AmwalPay online gateway plus a manual bank-transfer approval workflow with screenshot proof
• WhatsApp Commerce: two-way conversational commerce — availability, booking, order status, notifications,
broadcast marketing, and AI-assisted automation
• Admin Control Center: a single dashboard for operations, staff, CRM, marketing (email + WhatsApp) and
analytics
3. Business Objectives
• Enable customers to discover, check availability, and book tours/services online in under 3 minutes.
• Reduce manual coordination by allowing bookings and order tracking directly through WhatsApp.
• Support both digital payments (AmwalPay) and manual bank transfer to accommodate customers without cards
or with regional banking preferences.
• Give staff a shared inbox to manage all WhatsApp conversations without conflicts (assignment, labels, notes).
• Automate repetitive customer questions using an AI assistant and rule-based bot builder, escalating to a human
when needed.
• Provide the business owner with a single admin panel with full visibility and control: bookings, revenue, staff
performance, campaigns, and subscriber growth.
• Build a scalable base architecture that can add new tour categories, cities, currencies, and languages without a
rebuild.

6. Functional Requirements
6.1 Public Booking Website
• Homepage with featured tours/services, search, and category/city filters.
• Tour/service detail page: gallery, description, itinerary, inclusions/exclusions, pricing tiers (adult/child/group),
reviews/ratings.
• Real-time slot availability calendar per tour/service (date + time-slot level), showing remaining capacity.
• Multi-step booking flow: select date/slot → select quantity/pax → add-ons → customer details → payment
method → confirmation.
• Guest checkout and registered-account checkout (login/OTP or email).
• Cart/multi-item booking (book more than one tour/date in a single order) — optional but recommended.
• Coupon/discount code and promotional pricing support.
• Multi-language support (e.g., English/Arabic) and multi-currency display (e.g., OMR base currency).
• SEO-friendly URLs, meta tags, sitemap, and page-speed optimized image delivery.
• Customer account area: booking history, invoices/receipts, order status tracking, rebooking.
6.2 Slot & Availability Management
• Admin can define per-tour capacity: total slots per day, per time-slot, or per guide/vehicle resource.
• Auto-block/close-out when a slot reaches full capacity, with optional waitlist.
• Blackout dates, seasonal pricing, and recurring schedule templates (e.g., daily 9 AM/2 PM departures).
• Overbooking protection: seat count is locked/held for a short window during checkout to prevent double-
booking, released automatically if payment is not completed.
• Bulk slot creation/editing (e.g., generate 3 months of slots in one action) and bulk block-out.
• Live sync between website bookings and WhatsApp bookings — a seat booked from either channel instantly
reduces available inventory on both.
6.3 Booking & Order Management
• Central Order Management System: every booking (from website or WhatsApp) generates a unique Order ID
with full status lifecycle — Pending Payment → Payment Submitted → Verified/Paid → Confirmed →
Completed / Cancelled / Refunded / No-show.
• Order detail view: customer info, tour/slot, pax count, add-ons, price breakdown, payment method, payment
proof, staff notes, communication history (WhatsApp + email thread).
• Admin actions: approve/reject payment, modify booking (reschedule/date change), cancel with reason, issue
full/partial refund, resend confirmation, generate invoice/voucher PDF.
• Order Management API — REST/GraphQL endpoints so other systems (accounting software, tour-guide app,
reporting tools, future mobile app) can read/write order data securely (API key / OAuth2).
• Automatic reminders: pre-tour reminder (e.g., 24 hours before) via WhatsApp/email, and post-tour review
request.
• Booking source tracking (Website / WhatsApp / Admin-manual / API) for reporting.
6.4 Payment Management
6.4.1 AmwalPay Payment Gateway (Online)
• Integrate AmwalPay hosted checkout / API for card and local payment methods (as offered by AmwalPay in
Oman).

• Support authorization, capture, refund, and webhook/callback handling for payment status updates.
• Automatic order status update to "Confirmed" upon successful AmwalPay payment webhook, with instant email

• Handle failed/abandoned payments gracefully — retry payment link sent via email/WhatsApp.

6.4.2 Manual Bank Transfer + Screenshot Verification (Priority / Phase 1 Payment Method)
This is the payment flow explicitly requested as the first method to launch with:
• Bank account setup: Admin panel lets the business add one or more company bank accounts (bank name,
account name, account number/IBAN, branch) that are displayed to the customer at checkout
• Customer payment submission: Customer selects "Bank Transfer", views the account details, makes the
transfer, then submits a form with transaction reference/date and uploads a screenshot/photo of the payment
proof
• Pending state: Order is created in "Payment Submitted – Pending Verification" status; customer and admin both
notified instantly (admin gets a WhatsApp/email/dashboard alert)
• Admin verification: Verifier reviews the screenshot and reference in the order detail screen and clicks Approve
or Reject (with a reason/comment for rejection)
• Post-approval automation: On approval, the order status changes to "Confirmed" and the system automatically
sends a detailed confirmation via both Email and WhatsApp (order ID, tour, date/time, pax, amount paid,
voucher/QR code)
• On rejection: Customer is notified with the reason and instructions to resubmit or contact support
• Audit trail: Every verification action is logged with the staff name, timestamp, and decision for accountability
6.4.3 Payment Method Framework (Future-Proofing)
• Design the payment layer as a pluggable module so additional gateways (e.g., Thawani, PayTabs, Apple Pay, STC
Pay, or a second local PSP) can be added later without re-architecting.
• Support partial payment/deposit bookings (e.g., pay 25% now, balance before tour date) — suggested
enhancement.
6.5 WhatsApp Cloud API — Conversational Commerce
This is the core differentiator of the platform. All the following are handled via the official WhatsApp Business Cloud
API (Meta) through a Business Solution Provider (BSP) or direct Cloud API access:
6.5.1 Customer-Facing Conversational Features
• Check availability in chat: Customer types/selects a tour and date; bot replies with live slot availability pulled
from the same engine as the website
• Book directly in WhatsApp: Guided conversational flow (interactive list/buttons) to select tour → date/slot →
pax → add-ons → payment method → confirmation, without leaving WhatsApp
• Pay in chat: Send AmwalPay payment link, or accept bank-transfer screenshot directly as a chat attachment
which auto-attaches to the order
• Check order status/details in chat: Customer sends order ID or "my orders"; bot replies with full detail (status,
date, amount, voucher)
• Rich media & carousel messages: Product carousels (multiple tours with images, price, and a "Book Now" quick-
reply button), image/video/PDF itinerary sharing, location pins
• Order confirmation: Full detailed confirmation message automatically sent after approval (booking summary,
QR/voucher, support contact, cancellation policy)

6.5.2 Template Management
• Create, edit, and submit WhatsApp message templates (marketing, utility, authentication categories) for Meta
approval directly from the admin panel.
• Support template variables/placeholders (customer name, order ID, date, amount, etc.), header media
(image/video/document), and call-to-action / quick-reply buttons.
• Template library with status tracking (Draft / Pending Approval / Approved / Rejected) and version history.
• Sync approved templates automatically from Meta Business Manager into the platform (and vice versa).
6.5.3 Broadcast & Campaigns
• Send broadcast campaigns to segmented subscriber lists (e.g., past customers of a specific tour, inactive
customers, VIP customers) respecting WhatsApp's 24-hour session and template rules.
• Schedule broadcasts, view delivery/read/response analytics, and manage opt-out/unsubscribe automatically per
WhatsApp/Meta policy.
6.5.4 Subscriber & Contact Management
• Central WhatsApp subscriber database with tags, custom fields, consent/opt-in status, and conversation history.
• Import/export/sync contacts between website customer accounts, email subscribers, and WhatsApp contacts
(unified customer profile).
6.5.5 Staff Chat Management
• Shared team inbox: All incoming WhatsApp conversations appear in one inbox visible to authorized staff
• Chat assignment: Conversations can be manually or automatically (round-robin/load-based) assigned to a
specific staff member; reassignment supported
• Labels/tags: Custom labels (e.g., "New Lead", "Payment Pending", "VIP", "Complaint") for filtering and reporting
• Internal notes: Private notes on a conversation visible only to staff, not the customer
• Canned responses / quick replies: Predefined answers for FAQs to speed up agent response time
• Agent performance view: Response time, resolved chats, and conversion (chats → bookings) per staff member
6.5.6 Automation, Bot Builder & AI Assistant
• Visual bot/flow builder: Drag-and-drop conversation flow builder (trigger → condition → action) for FAQs,
booking flows, and follow-ups, requiring no coding
• Keyword & intent triggers: Bot responds to keywords, button clicks, or detected intent (e.g., "availability",
"price", "cancel")
• AI Assistant (LLM-powered): Handles natural-language questions ("Do you have a desert safari this weekend for
4 people?"), pulls live data (availability/pricing) via API/function-calling, and can complete a booking
conversationally
• Human handoff: Bot detects when it cannot resolve a query (or customer requests a human) and hands the chat
to an available agent, with full context passed along
• Business hours & auto-reply: Away messages outside working hours, with option to still allow AI-handled
bookings 24/7
6.6 Email Management
• Template builder: Drag-and-drop / HTML email editor for transactional and marketing templates, with variable
placeholders and preview
• Template sync: Reusable template blocks shared between transactional emails (confirmations, receipts) and
marketing campaigns

6.7 Unified Order Confirmation Flow
As specifically requested — once a customer submits booking + payment details (online or bank-transfer screenshot)
and the admin approves it, the system automatically triggers:
• An Email confirmation with: Order ID, tour name, date/time/slot, number of pax, add-ons, total amount paid,
payment method, meeting point/instructions, cancellation policy, support contact, and a downloadable PDF
voucher/invoice.
• A WhatsApp confirmation message (using an approved template) with the same key details, optionally including
a QR code/voucher image and quick links (Get Directions / Contact Support / Reschedule).
• An internal notification to the assigned staff member / operations team so the field logistics (guide, vehicle) can
be arranged.

7. Suggested Additional Features (Recommended Enhancements)
Based on the requirements shared, here are gaps and value-adding features worth considering before development
begins:
• Digital voucher with QR check-in: Generate a scannable QR code per booking that field staff can scan on the day
of the tour to confirm attendance/no-show — closes the loop between booking and delivery
• Deposit / partial payment support: Allow a customer to pay a percentage upfront and balance later, common
for tour bookings — reduces drop-off at checkout
• Dynamic/seasonal pricing rules: Auto-adjust prices by date, demand, or remaining capacity (e.g., higher price
on weekends/holidays)
• Waitlist & auto-notify: When a slot is full, let customers join a waitlist and get an automatic WhatsApp/email
alert if a seat opens up (cancellation)
• Reviews & ratings with photo upload: Post-tour review requests (auto-sent via WhatsApp/email) feed public
star ratings on the tour page — builds trust and SEO
• Referral & loyalty program: Reward repeat customers or referrals with discount codes distributed via
WhatsApp/email
• Abandoned booking recovery: Auto-detect incomplete bookings (slot selected, payment not completed) and
send a reminder via WhatsApp/email with a direct resume link
• Fraud/duplicate-screenshot detection: Basic checks (hash comparison, OCR of amount/reference vs submitted
order) to flag suspicious manual-payment submissions before admin review
• Multi-branch / multi-location support: If the business operates in more than one city/branch, structure data so
each branch has its own inventory, staff, and bank account, with combined reporting

• Guide/vehicle resource management: Beyond "slots", track which guide/vehicle is assigned to each departure

• Customer self-service reschedule/cancel: Allow customers to reschedule or cancel within policy directly from

9.2 Key Integration Flows
• AmwalPay flow: Checkout → create payment session via AmwalPay API → redirect/host page → customer pays
→ AmwalPay sends signed webhook → system verifies signature → order status updated → confirmation
triggered
• Manual bank transfer flow: Checkout → customer selects bank transfer → sees account details → submits
reference + screenshot → order created as Pending Verification → admin dashboard alert → admin
approves/rejects → confirmation or rejection notice triggered
• WhatsApp booking flow: Customer message → Cloud API webhook → bot/flow engine (or AI assistant) → calls
internal Booking API for availability/creation → payment link or bank-transfer instructions sent in chat →
screenshot received as media message → attached to order automatically

12. Assumptions & Constraints
• This is treated as a single-business (not multi-vendor) platform unless clarified otherwise.
• AmwalPay merchant account and API credentials will be provided by the business/AmwalPay onboarding team.
• WhatsApp Cloud API access requires a verified Meta Business Manager account, a dedicated business phone
number, and either direct Cloud API access or a licensed BSP — this has an approval lead time and template-
approval process outside the development team's control.
• AI Assistant responses must stay within business-provided data (tours, pricing, policies) to avoid giving incorrect
commitments to customers.
• Company bank account details for manual transfer will be provided by finance and are editable only by Super
Admin.
• Primary languages assumed as English and Arabic; other languages can be added later.
