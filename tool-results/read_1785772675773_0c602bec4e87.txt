    26→2. Executive Summary
    27→This document defines the business and functional requirements for a production-grade, web-based Tour & Activity
    28→Booking Platform. The platform allows customers to browse tours/services, check real-time slot availability, book
    29→online, and pay either through the AmwalPay payment gateway or via a manual bank-transfer-with-screenshot
    30→workflow that is verified by an admin. It integrates deeply with the WhatsApp Cloud API so that customers can check
    31→availability, book, and track orders directly inside WhatsApp chat, supported by rich message templates (including
    32→media and carousels), a bot/automation builder, and an AI chat assistant. A full-featured admin panel gives the
    33→business owner complete control over bookings, orders, payments, staff, WhatsApp/email marketing, and reporting.
    34→The system is designed around four pillars:
    35→• Booking Engine: slot-based availability, multi-service booking, and order lifecycle management
    36→• Payments: AmwalPay online gateway plus a manual bank-transfer approval workflow with screenshot proof
    37→• WhatsApp Commerce: two-way conversational commerce — availability, booking, order status, notifications,
    38→broadcast marketing, and AI-assisted automation
    39→• Admin Control Center: a single dashboard for operations, staff, CRM, marketing (email + WhatsApp) and
    40→analytics
    41→3. Business Objectives
    42→• Enable customers to discover, check availability, and book tours/services online in under 3 minutes.
    43→• Reduce manual coordination by allowing bookings and order tracking directly through WhatsApp.
    44→• Support both digital payments (AmwalPay) and manual bank transfer to accommodate customers without cards
    45→or with regional banking preferences.
    46→• Give staff a shared inbox to manage all WhatsApp conversations without conflicts (assignment, labels, notes).
    47→• Automate repetitive customer questions using an AI assistant and rule-based bot builder, escalating to a human
    48→when needed.
    49→• Provide the business owner with a single admin panel with full visibility and control: bookings, revenue, staff
    50→performance, campaigns, and subscriber growth.
    51→• Build a scalable base architecture that can add new tour categories, cities, currencies, and languages without a
    52→rebuild.

    97→6. Functional Requirements
    98→6.1 Public Booking Website
    99→• Homepage with featured tours/services, search, and category/city filters.
   100→• Tour/service detail page: gallery, description, itinerary, inclusions/exclusions, pricing tiers (adult/child/group),
   101→reviews/ratings.
   102→• Real-time slot availability calendar per tour/service (date + time-slot level), showing remaining capacity.
   103→• Multi-step booking flow: select date/slot → select quantity/pax → add-ons → customer details → payment
   104→method → confirmation.
   105→• Guest checkout and registered-account checkout (login/OTP or email).
   106→• Cart/multi-item booking (book more than one tour/date in a single order) — optional but recommended.
   107→• Coupon/discount code and promotional pricing support.
   108→• Multi-language support (e.g., English/Arabic) and multi-currency display (e.g., OMR base currency).
   109→• SEO-friendly URLs, meta tags, sitemap, and page-speed optimized image delivery.
   110→• Customer account area: booking history, invoices/receipts, order status tracking, rebooking.
   111→6.2 Slot & Availability Management
   112→• Admin can define per-tour capacity: total slots per day, per time-slot, or per guide/vehicle resource.
   113→• Auto-block/close-out when a slot reaches full capacity, with optional waitlist.
   114→• Blackout dates, seasonal pricing, and recurring schedule templates (e.g., daily 9 AM/2 PM departures).
   115→• Overbooking protection: seat count is locked/held for a short window during checkout to prevent double-
   116→booking, released automatically if payment is not completed.
   117→• Bulk slot creation/editing (e.g., generate 3 months of slots in one action) and bulk block-out.
   118→• Live sync between website bookings and WhatsApp bookings — a seat booked from either channel instantly
   119→reduces available inventory on both.
   120→6.3 Booking & Order Management
   121→• Central Order Management System: every booking (from website or WhatsApp) generates a unique Order ID
   122→with full status lifecycle — Pending Payment → Payment Submitted → Verified/Paid → Confirmed →
   123→Completed / Cancelled / Refunded / No-show.
   124→• Order detail view: customer info, tour/slot, pax count, add-ons, price breakdown, payment method, payment
   125→proof, staff notes, communication history (WhatsApp + email thread).
   126→• Admin actions: approve/reject payment, modify booking (reschedule/date change), cancel with reason, issue
   127→full/partial refund, resend confirmation, generate invoice/voucher PDF.
   128→• Order Management API — REST/GraphQL endpoints so other systems (accounting software, tour-guide app,
   129→reporting tools, future mobile app) can read/write order data securely (API key / OAuth2).
   130→• Automatic reminders: pre-tour reminder (e.g., 24 hours before) via WhatsApp/email, and post-tour review
   131→request.
   132→• Booking source tracking (Website / WhatsApp / Admin-manual / API) for reporting.
   133→6.4 Payment Management
   134→6.4.1 AmwalPay Payment Gateway (Online)
   135→• Integrate AmwalPay hosted checkout / API for card and local payment methods (as offered by AmwalPay in
   136→Oman).
   137→
   138→========== PAGE 7 ==========
   139→• Support authorization, capture, refund, and webhook/callback handling for payment status updates.
   140→• Automatic order status update to "Confirmed" upon successful AmwalPay payment webhook, with instant email
   141→+ WhatsApp confirmation.
   142→• Handle failed/abandoned payments gracefully — retry payment link sent via email/WhatsApp.
   143→• Payment reconciliation report matching AmwalPay settlement reports against internal orders.
   144→6.4.2 Manual Bank Transfer + Screenshot Verification (Priority / Phase 1 Payment Method)
   145→This is the payment flow explicitly requested as the first method to launch with:
   146→• Bank account setup: Admin panel lets the business add one or more company bank accounts (bank name,
   147→account name, account number/IBAN, branch) that are displayed to the customer at checkout
   148→• Customer payment submission: Customer selects "Bank Transfer", views the account details, makes the
   149→transfer, then submits a form with transaction reference/date and uploads a screenshot/photo of the payment
   150→proof
   151→• Pending state: Order is created in "Payment Submitted – Pending Verification" status; customer and admin both
   152→notified instantly (admin gets a WhatsApp/email/dashboard alert)
   153→• Admin verification: Verifier reviews the screenshot and reference in the order detail screen and clicks Approve
   154→or Reject (with a reason/comment for rejection)
   155→• Post-approval automation: On approval, the order status changes to "Confirmed" and the system automatically
   156→sends a detailed confirmation via both Email and WhatsApp (order ID, tour, date/time, pax, amount paid,
   157→voucher/QR code)
   158→• On rejection: Customer is notified with the reason and instructions to resubmit or contact support
   159→• Audit trail: Every verification action is logged with the staff name, timestamp, and decision for accountability
   160→6.4.3 Payment Method Framework (Future-Proofing)
   161→• Design the payment layer as a pluggable module so additional gateways (e.g., Thawani, PayTabs, Apple Pay, STC
   162→Pay, or a second local PSP) can be added later without re-architecting.
   163→• Support partial payment/deposit bookings (e.g., pay 25% now, balance before tour date) — suggested
   164→enhancement.
   165→6.5 WhatsApp Cloud API — Conversational Commerce
   166→This is the core differentiator of the platform. All the following are handled via the official WhatsApp Business Cloud
   167→API (Meta) through a Business Solution Provider (BSP) or direct Cloud API access:
   168→6.5.1 Customer-Facing Conversational Features
   169→• Check availability in chat: Customer types/selects a tour and date; bot replies with live slot availability pulled
   170→from the same engine as the website
   171→• Book directly in WhatsApp: Guided conversational flow (interactive list/buttons) to select tour → date/slot →
   172→pax → add-ons → payment method → confirmation, without leaving WhatsApp
   173→• Pay in chat: Send AmwalPay payment link, or accept bank-transfer screenshot directly as a chat attachment
   174→which auto-attaches to the order
   175→• Check order status/details in chat: Customer sends order ID or "my orders"; bot replies with full detail (status,
   176→date, amount, voucher)
   177→• Rich media & carousel messages: Product carousels (multiple tours with images, price, and a "Book Now" quick-
   178→reply button), image/video/PDF itinerary sharing, location pins
   179→• Order confirmation: Full detailed confirmation message automatically sent after approval (booking summary,
   180→QR/voucher, support contact, cancellation policy)
   181→

   183→6.5.2 Template Management
   184→• Create, edit, and submit WhatsApp message templates (marketing, utility, authentication categories) for Meta
   185→approval directly from the admin panel.
   186→• Support template variables/placeholders (customer name, order ID, date, amount, etc.), header media
   187→(image/video/document), and call-to-action / quick-reply buttons.
   188→• Template library with status tracking (Draft / Pending Approval / Approved / Rejected) and version history.

   190→6.5.3 Broadcast & Campaigns
   191→• Send broadcast campaigns to segmented subscriber lists (e.g., past customers of a specific tour, inactive
   192→customers, VIP customers) respecting WhatsApp's 24-hour session and template rules.
   193→• Schedule broadcasts, view delivery/read/response analytics, and manage opt-out/unsubscribe automatically per
   194→WhatsApp/Meta policy.
   195→6.5.4 Subscriber & Contact Management
   196→• Central WhatsApp subscriber database with tags, custom fields, consent/opt-in status, and conversation history.
   197→• Import/export/sync contacts between website customer accounts, email subscribers, and WhatsApp contacts
   198→(unified customer profile).
   199→6.5.5 Staff Chat Management
   200→• Shared team inbox: All incoming WhatsApp conversations appear in one inbox visible to authorized staff
   201→• Chat assignment: Conversations can be manually or automatically (round-robin/load-based) assigned to a
   202→specific staff member; reassignment supported
   203→• Labels/tags: Custom labels (e.g., "New Lead", "Payment Pending", "VIP", "Complaint") for filtering and reporting
   204→• Internal notes: Private notes on a conversation visible only to staff, not the customer
   205→• Canned responses / quick replies: Predefined answers for FAQs to speed up agent response time
   206→• Agent performance view: Response time, resolved chats, and conversion (chats → bookings) per staff member
   207→6.5.6 Automation, Bot Builder & AI Assistant
   208→• Visual bot/flow builder: Drag-and-drop conversation flow builder (trigger → condition → action) for FAQs,
   209→booking flows, and follow-ups, requiring no coding
   210→• Keyword & intent triggers: Bot responds to keywords, button clicks, or detected intent (e.g., "availability",
   211→"price", "cancel")
   212→• AI Assistant (LLM-powered): Handles natural-language questions ("Do you have a desert safari this weekend for
   213→4 people?"), pulls live data (availability/pricing) via API/function-calling, and can complete a booking
   214→conversationally
   215→• Human handoff: Bot detects when it cannot resolve a query (or customer requests a human) and hands the chat
   216→to an available agent, with full context passed along
   217→• Business hours & auto-reply: Away messages outside working hours, with option to still allow AI-handled
   218→bookings 24/7
   219→6.6 Email Management
   220→• Template builder: Drag-and-drop / HTML email editor for transactional and marketing templates, with variable
   221→placeholders and preview
   222→• Template sync: Reusable template blocks shared between transactional emails (confirmations, receipts) and
   223→marketing campaigns

   228→• Subscriber manager: List management, custom fields, tags, double opt-in, unsubscribe handling, GDPR/PDPL-

   271→• Deposit / partial payment support: Allow a customer to pay a percentage upfront and balance later, common
   272→for tour bookings — reduces drop-off at checkout
   273→• Dynamic/seasonal pricing rules: Auto-adjust prices by date, demand, or remaining capacity (e.g., higher price
   274→on weekends/holidays)
   275→• Waitlist & auto-notify: When a slot is full, let customers join a waitlist and get an automatic WhatsApp/email
   276→alert if a seat opens up (cancellation)
   277→• Reviews & ratings with photo upload: Post-tour review requests (auto-sent via WhatsApp/email) feed public
   278→star ratings on the tour page — builds trust and SEO
   279→• Referral & loyalty program: Reward repeat customers or referrals with discount codes distributed via
   280→WhatsApp/email
   281→• Abandoned booking recovery: Auto-detect incomplete bookings (slot selected, payment not completed) and
   282→send a reminder via WhatsApp/email with a direct resume link
   283→• Fraud/duplicate-screenshot detection: Basic checks (hash comparison, OCR of amount/reference vs submitted
   284→order) to flag suspicious manual-payment submissions before admin review
   285→• Multi-branch / multi-location support: If the business operates in more than one city/branch, structure data so
   286→each branch has its own inventory, staff, and bank account, with combined reporting

   429→commitments to customers.
